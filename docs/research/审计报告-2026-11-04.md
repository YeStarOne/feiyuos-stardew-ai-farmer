## 一、能立刻解决现有痛点的端点（按价值排序）

### 🥇 P0-1 `/sell` —— 卖货不需要物理点击（消除前台互锁！）

**源码**（HandleSell）：
```csharp
Farm farm = currentLocation as Farm;
IInventory bin = farm?.getShippingBin(player);
if (bin == null) → { ok:false, error:"No shipping bin found (must be on Farm)" }
foreach (slot) { if (!Tool && !category ∈ {-99,-98,-97,-96} && 名字匹配)
    bin.Add(item);  player.Items[i] = null; }
→ { ok:true, sold:[{item,count,price}], totalItems }
```

**关键**：
- `bin.Add()` 是**直接往出货箱的 inventory 里塞**，零点击、零 UI、零前台依赖。
- 下次睡觉结算时，出货箱里的东西照常结算成钱。
- **必须按名字逐个投**（`{name:"Parsnip"}`）。**绝对不能传 `all:true`** —— 源码里 `sellAll` 分支会跳过名字过滤，把包里除了种子/工具/任务品之外**全部**塞进去，直接违反我们的白名单政策。
- 必须在 Farm 地图上（`getShippingBin` 只对 Farm 有效）。

**影响**：`lib.mjs` 的 `openBin()`（物理右键 + 前台互锁 + DPI 换算 + 多 pass 重开）**整套可以退休**。这是我们卡了最久的问题（连续多日"卖货等前台空闲"）。

### 🥇 P0-2 `/cancel_sleep` —— 赖床死循环一行破解

**源码**（HandleCancelSleep）：一次性做四件事
```csharp
player.isInBed.Value = false;
if (activeClickableMenu is ReadyCheckDialog rc) rc.exitThisMenu(true);
Game1.activeClickableMenu = null;
Game1.dialogueUp = false;
```

这正是我们在"春2 一晚跳到夏2、31 株作物全灭"事故里**手工拼出来的四步**（menu_close ×2 + warp 下床 + 关对话框）。现在有原子端点。

配套 `/ready_state` 能读出 `NumberReady / NumberRequired / Locking / ActiveLockId / ReadyStates` —— 睡觉卡 1/2 时能立刻知道是**谁没 ready**、**锁在哪个 check id**，不用猜。

### 🥈 P1-1 `/farm_report` —— 全农场地形统计，终结"30 株没浇水"误报

**源码**：遍历 `ResolveLocations("")`（**所有地图，不只当前图**），调 `ScanLocationCrops` 汇总：
```
crops: { total, watered, ready, byLocation }
animals: { total, animals:[...] }
machines: { total, machines:[...] }
season / dayOfMonth / year
```
一次调用拿到全农场 `总株数 / 已浇水数 / 可收数`。我们之前的 `waterAll` 只扫半径 10-12，才会把"半径外没扫到"误判成"没浇水"（当时还怀疑桥没 `watered` 字段）。

### 🥈 P1-2 `/ripen?radius=30` —— 季末强制催熟

**源码**：`crop.growCompletely()` 直接调用游戏自己的成熟方法，对半径内所有未熟作物生效。
```
{ ok:true, ripened: N }
```
季末最后一天（春28/夏28）不用再赌"今晚会不会熟"，直接催熟 → `/harvest` 收 → `/sleep` 存档锁住。

> 注意：这是明确的作弊能力。建议只在**季末保收成**这种止损场景用，平时不用。

---

### 🥈 P1-3 `/clear_ground?x=&y=` —— 直接删格上杂物

**源码**：从 `location.debris`、`location.objects`、`location.terrainFeatures` 三处**直接 Remove** 目标格。
```
{ ok:true, cleared: N }
```
一次一格，但**不用镰刀、不用工具、不用走路、不用蓄力**。清一片 N 格 = N 次 HTTP 循环（每格一次主线程 enqueue，很快）。
这比"行为学框选割草"轻得多 —— 后者要求游戏窗口在前台（源码 `Tick` 传 `IsActive`），而这个是纯 HTTP。

> ⚠️ 它删的是 `objects`（含宝箱/机器！）和 `terrainFeatures`（含作物！）。**只能对确认是杂草/石头/树枝的格子调用**，调之前必须 `/dump_tile` 或 `/surroundings` 核对该格内容。

### 🥈 P1-4 `/tool_area` 参数名是 `operation`（不是我猜的 `ops`）

**源码**：
```csharp
string operation = GetParam<string>(p, "operation");
if (operation != "water" && operation != "till") → 拒绝
Tool t = player.CurrentTool;  // 不是水壶/锄头就自动切到包里的
(int dx,int dy,int power) = t.UpgradeLevel switch { 0=>(1,1,0), ... }  // 按升级等级算蓄力范围
```
**两个修正**：
1. 参数是 `operation`，不是 `ops`。我 11-04 在 fish-eye 里写错了 → 已修。
2. 它会**自动切换工具**、**按水壶/锄头升级等级自动换算蓄力范围**，不需要我们先 `/select`。

### 🥉 P2-1 `/scan_chests` —— 一次列出所有箱子及内容

**源码**：`CollectStorageChests(location)` → 每个箱子给 `{name, color, autoTag, capacity, freeSlots, items:[{name,count,slot,quality,qualifiedId}]}`
配套 `/chest_take_list {items:[{name,count}]}` 能按名字批量取（有 `reachTiles` 概念，会走到够得着的地方；`tooFar` 会明确报）。

我们现在的 `findChest()` 是 `/surroundings` 里正则匹配 "Chest"，只能看到视野内的；而且存箱要靠 `storeToChest` 一次一件。

### 🥉 P2-2 `/sprinklers` —— 洒水器精确布点

**源码**：遍历 `location.Objects`，对 `Name.Contains("Sprinkler")` 的给出 `{x,y,type: iridium|quality|basic}`。
我们目前是靠 `/surroundings` 扫到 `object` 含 "Sprinkler" 再手算 4 邻格（`plant-spring.mjs` 里硬编码了 7 个坐标）。有这端点就不用手写坐标表。

### 🥉 P2-3 `/machines` + `/machine_reqs` + `/machine_load` —— 熔炉/腌罐全自动投料

- `/machine_reqs`：给每个机器 `{need:[{id,name,have,enough}]}` —— **直接告诉你投什么料**
- `/machine_load`：按 `{x,y,name,count}` 投，返回 `{loaded, emptySeen, noSlot, rejected, remaining}`

我们的 `craft-smelt.mjs` 现在是硬编码坐标 + 手动 `/interact` + 逐格回查。有这三个端点可以直接做成"缺什么料→自动投→收成品"的闭环。

## 二、必须永久禁用的端点（危险）

| 端点 | 危险点 | 结论 |
|---|---|---|
| `/money {amount}` | `player.Money += amount` 直接改钱 | **永久禁用**。经济系统会彻底失真，与"自己种田赚钱"的项目目标冲突 |
| `/sell {all:true}` | 跳过名字过滤，卖光非种子非工具非任务品 | **永久禁用 `all`**。只能逐个按名字投 |
| `/clear_ground` | 直接 Remove objects/terrainFeatures | **限定使用**：只对已核实的杂草/石头/树枝格；禁止对含作物/箱子/机器的格调用 |
| `/drop` / `/drop_item` | 把物品丢到地上（debris） | 谨慎。我们的"绝不丢用户物品"政策要求先核对名字 |
| `/sell_to_shop` | 需要 `ShopMenu` 已开着 + `receiveLeftClick` 物理点击 | 依赖 UI，不比 `/sell` 好，不用 |

## 五、方法学教训

**不要靠扒字符串猜端点语义。** 这次 `ilspycmd` 反编译后才发现：
1. `/sell` 是直接塞出货箱（我们一直以为它"可能绕白名单"而不敢用，实际是**最安全的卖货通道**）
2. `/tool_area` 参数是 `operation`（我按 `ops` 写错了，fish-eye 里的批量浇水其实一直没生效）
3. `/cancel_sleep` 一次性做完四步（我们手工拼了两周）
4. `/farm_report` 扫全农场（我们一直在扫半径 10）

**规则**：以后遇到"这个端点不确定行为"的情况，第一反应应该是 `ilspycmd` 反编译，而不是写试探脚本。反编译一次 30 秒，试探一次可能烧掉一个游戏日。
